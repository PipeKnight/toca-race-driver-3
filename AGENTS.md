# Обязательные правила проекта TOCA Race Driver 3 (PS2)

Правила действуют для всего репозитория. Требования к запуску, упаковке и проверкам применяются по мере появления соответствующих компонентов.

## Шесть пунктов открытого письма

1. **Одна точка входа.** Поставляйте один пользовательский исполняемый файл на платформу и архитектуру. Он запускает первичную подготовку по необходимости и открывает игру напрямую после неё. Пользователь и сторонний лаунчер всегда вызывают один и тот же файл. Внутренние процессы и отдельные сборки для разработчиков допустимы.
2. **Портативность по умолчанию.** Храните настройки, сохранения, кэш, логи, извлечённые ресурсы, результаты подготовки, обновления и временные файлы внутри выбранного каталога игры. По умолчанию используйте каталог исполняемого файла независимо от текущего рабочего каталога. Для AppImage принимайте явный каталог данных, в том числе на другом диске или SD-карте. Запись в AppData, Documents, системный TEMP или XDG-каталоги допустима только в явно выбранном системном режиме, например при установке через пакетный менеджер.
3. **Два формата релиза для Linux.** Публикуйте AppImage и `.tar.gz` с готовой сборкой одной версии. Архив должен работать после распаковки, в том числе при установке из лаунчера внутри Flatpak. Проверяйте, что архив релиза содержит исполняемый файл и нужные зависимости.
4. **Настройки и запуск через CLI.** Дайте стабильные флаги для полноэкранного и оконного режима, пути к образу или извлечённым файлам, каталога данных и подготовки, прямого запуска и остальных пользовательских настроек. Описывайте флаги в `--help`. Для автоматизации возвращайте понятные сообщения и коды выхода без обязательных окон и диалогов.
5. **Нативный Linux.** Сохраняйте сборку для Linux рабочей с первых изменений, которые вводят платформенные зависимости. Проверяйте Windows и Linux в CI, а для релиза проверяйте запуск на SteamOS или Bazzite. Если нативный Linux-билд временно недоступен, проверяйте и документируйте запуск через Proton.
6. **Работа с сообществом.** Перед стартом проекта и крупной подсистемы проверяйте, ведётся ли уже такая работа. При наличии подходящего проекта предлагайте сотрудничество. По спорным вопросам упаковки и интеграции заранее сверяйтесь с разработчиками профильных инструментов, например в канале для разработчиков RecompLauncher. Ведите публичную дорожную карту и обновляйте статус проекта по мере готовности.

## Дополнения из комментариев

7. **Прозрачная работа с диском.** Принимайте образ и каталог извлечённых файлов. Документируйте список поддерживаемых регионов, серийных номеров, ревизий и контрольных сумм. Сообщайте, нужен ли оригинал при каждом запуске или только при подготовке, что она создаст и сколько места потребует. Открывайте оригинал для чтения и переиспользуйте полученные данные при следующих запусках. Предусмотрите чтение сжатых образов, например CHD, без обязательной распаковки второго полного образа. Расширяйте поддержку регионов с учётом языков PAL-версий.
8. **Готовность к запуску без среды разработки.** Пользовательский релиз должен содержать необходимые зависимости или самостоятельно выполнять подготовку из легальной копии. Запуск на SteamOS не должен требовать установки компилятора или CMake. В Git и релизах храните материалы проекта, на распространение которых есть права. Оригинальный ELF и игровые ресурсы извлекайте локально из диска пользователя. Для проверки в PCSX2 используйте BIOS, снятый с собственной консоли.
9. **Обновления по выбору пользователя.** Предусмотрите обновление из приложения и возможность его пропустить или отключить для внешних лаунчеров. При обновлении сохраняйте настройки и сохранения и убирайте устаревшие файлы самого приложения. Проверяйте этот сценарий в игровом режиме SteamOS и под Proton, если он поддерживается. Для внешних лаунчеров документируйте стабильную точку запуска, пути к данным и способ узнать версию.
10. **Управление и выход.** Запуск, основные меню и выход из игры должны работать с контроллера. На ПК обеспечьте управление мышью и клавиатурой, переназначение кнопок, подсказки для текущего устройства ввода и режим окна без рамки по умолчанию с возможностью переключения. Храните прогресс в обычных локальных файлах и обеспечьте доступ к сохранению и выходу без переключения из игры.
11. **Производительность и совместимость.** Сначала обеспечьте стабильную гонку, корректное сохранение и предсказуемую производительность. Затем добавляйте расширенные модификации и дополнительные эффекты. Если компиляция шейдеров вызывает рывки, предусмотрите запускаемую пользователем предварительную компиляцию и повторное использование кэша. При выборе графического API учитывайте устройства без Vulkan и предусмотрите OpenGL, если его позволяет выбранный стек. Поддержку CRT и пресетов `.slang` рассматривайте как опции, когда базовый рендеринг стабилен.
12. **Проверяемый статус.** Для каждого релиза публикуйте проверенные платформы и ревизии диска, известные ограничения и фактическую степень готовности. Документируйте путь от чистой установки до запуска, повторного запуска, обновления и удаления переносимой копии. Начните проверку с `SLUS-21182` версии `1.02`. Каждую следующую ревизию проверяйте отдельно перед добавлением в список поддерживаемых.
